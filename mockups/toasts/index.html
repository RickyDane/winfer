Toast notifications: three directions

Today render_toasts (ui/overlays.rs) draws one plain text line per card, so markdown from agents shows raw. All three variants share the same data drawn from real call sites, render markdown (bold, code, links), and pause on hover. Use Replay to watch the “Pushing…” toast turn into “Pushed”.

A · Compact pills

MINIMAL

Pros

  • Smallest change from today; covers least of the terminal
  • Kind icon makes errors scannable
  • Thin drain bar is the countdown

Cons

  • Single line ellipsizes long errors (expands to rounded card only if there's a detail)
  • One action max; no chips for agent events

API

Toast { kind, title, detail: Option<md>, action: Option<(label, Command)>, id: Option<key> }
toast(text) → kind inferred: "Couldn't…/failed/not possible" → Error, "Merged/Copied/…ed" → Success, ends with "…" → Progress; first line = title, rest = detail.

B · Rich cards with accent edge

RECOMMENDED

Pros

  • Title + markdown body + several actions + chips: fits agent/task events and errors with a detail line
  • Error detail in a mono block (copyable)
  • Progress toasts update in place by id, with a bar

Cons

  • Taller; 4 cards cover ~300px of the right pane
  • Needs the most call-site migration to look its best

API

enum ToastKind { Success, Error, Info, Warning, Progress(Option<f32>), Agent }
Toast { id, kind, title, detail: Option<md>, chips: Vec<Chip>, actions: Vec<(label, Command)> }
toast(text) stays (Info, kind inferred as in A); add toast_ok / toast_err(title, err) and toast_update(id, …). Migrate the ~40 obvious "Couldn't …: {err}" sites to toast_err so {err} becomes the detail.

C · Notification center

HISTORY

Pros

  • Never more than one card's height on screen; the rest fan out on hover
  • Nothing lost: inbox keeps today's toasts (missed errors, agent events)
  • Unread dot in the titlebar

Cons

  • Hides urgency: a second error sits under the top card
  • New UI surface (bell + inbox panel) and state to persist

API

Same Toast as B, plus { at: Instant, read: bool }; toasts move to self.inbox on expiry instead of being dropped (cap 100). toast(text) unchanged; transient-only hints ("Command copied") flagged ephemeral so they skip the inbox.
